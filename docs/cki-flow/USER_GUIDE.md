# CKI Flow — руководство пользователя

**Версия приложения:** 1.1  
**Для кого:** Product Manager и члены команды ЦКИ, которые планируют кварталы, спринты, релизы и нагрузку.

Это руководство написано простым языком. Технические детали разработки сюда не входят — только то, что нужно, чтобы начать работать в программе после установки.

---

## 1. Что это за программа

**CKI Flow** — настольное приложение для ежедневной работы Product Manager:

- ведение бэклога User Story;
- автоматическое создание связанных задач (анализ, разработка, тестирование и т.д.);
- планирование спринтов и кварталов;
- контроль загрузки команды;
- отслеживание релизов и рисков;
- импорт старых планов из PDF/JSON.

Данные хранятся **локально на вашем компьютере** (в браузерном хранилище приложения). Сервер не требуется.

Интерфейс программы — **на русском языке**.

## 2. Установка и запуск

### macOS

1. Найдите приложение **CKI Flow** в папке «Программы» (`/Applications/CKI Flow.app`)  
   или откройте файл установки `.dmg` и перетащите приложение в «Программы».
2. Запустите **CKI Flow**.
3. При первом запуске macOS может предупредить, что приложение загружено из интернета.  
   Разрешите открытие через **Системные настройки → Конфиденциальность и безопасность** (или через контекстное меню → «Открыть»).

### Что вы увидите при первом запуске

Программа откроется с **демо-данными** продукта CKI:

- активный квартал и спринт;
- несколько сотрудников;
- шаблоны процессов и оценок;
- примеры инициатив и эпиков.

Можно сразу пробовать сценарии на демо или сбросить данные позже (см. раздел «Настройки»).

## 3. Как устроен экран

```
┌────────────┬──────────────────────────────────────────────┐
│            │  Верхняя панель: квартал · спринт · релиз    │
│  Меню      ├──────────────────────────────────────────────┤
│  слева     │  Хлебные крошки · недавние объекты           │
│            ├──────────────────────────────────────────────┤
│  Сегодня   │                                              │
│  План      │           Основная рабочая область           │
│  Поставка  │                                              │
│  Аналитика │                                              │
│  Система   │                                              │
└────────────┴──────────────────────────────────────────────┘
```

### Левое меню

| Раздел | Экраны | Зачем |
|--------|--------|--------|
| **Сегодня** | Сегодня | Сводка «что происходит сейчас» |
| **План** | Квартал, Спринт | Планирование периода |
| **Поставка** | Бэклог, Доска, Дорожная карта, Релизы | Работа по User Story и поставке |
| **Аналитика** | Загрузка, Риски, Пульс | Нагрузка и здоровье плана |
| **Система** | Команда, Шаблоны, Миграция, Настройки | Настройка и данные |

Меню можно свернуть кнопкой с иконкой панели в левом верхнем углу.

### Верхняя панель

- **Переключатель квартала** — какой квартал сейчас «активный».
- **Переключатель спринта** — какой спринт сейчас «активный».
- **Ссылка на релиз** — быстрый переход к активному релизу.
- **Команды (⌘K)** — быстрый поиск действий и переходов.
- **Тема** — светлая / тёмная.
- **Версия** — номер сборки (например, v1.1.0).

### Хлебные крошки и «Недавние»

Под верхней панелью:

- **крошки** показывают, где вы сейчас (например: CKI Flow → Поставка → Бэклог);
- **Недавние** — последние открытые User Story и другие объекты для быстрого возврата.

## 4. Основные понятия (простыми словами)

| Понятие | Что это |
|---------|---------|
| **User Story** | Карточка потребности: «Как … я хочу … чтобы …». Главная единица планирования. |
| **Задача (Work Item)** | Конкретная работа внутри Story: бизнес-анализ, разработка, тестирование и т.п. |
| **Шаблон процесса (Workflow)** | Набор задач и зависимостей, который создаётся автоматически при создании Story. |
| **Шаблон оценки** | Готовые часы по этапам (например, «API»: BA 4 ч, Dev 16 ч…). |
| **Спринт** | Короткий период поставки (обычно 1–2 недели). |
| **Квартал** | Три месяца планирования (Q1–Q4). |
| **Инициатива / Epic** | Крупные цели и группы Story внутри квартала. |
| **Релиз** | Набор Story, который планируется выпустить вместе. |
| **Capacity** | Сколько часов команда реально может взять с учётом отпусков и частичной занятости. |
| **Зависимость** | Связь «сначала A, потом B». Система не даёт создать цикл. |

## 5. Типичный день Product Manager

Ниже — рекомендуемый порядок работы. Можно начинать с любого шага.

### Утро: экран «Сегодня»

Откройте **Сегодня**. Здесь видно:

- активный квартал и спринт;
- сколько User Story и задач;
- загрузку команды и **перегруженных сотрудников**;
- готовность релиза;
- число заблокированных задач и блокирующих зависимостей;
- недавние Story;
- форму быстрого создания новой Story.

**Что делать:**

1. Посмотреть, нет ли перегрузок и блокировок.
2. При необходимости перейти в релиз, доску или спринт одной кнопкой.
3. Создать новую Story прямо с этого экрана (форма справа).

### Планирование спринта

1. Откройте **План → Спринт**.
2. Слева — **готовый бэклог** (Story, которые можно взять).
3. Справа — **объём текущего спринта**.
4. Нажмите **«В спринт»** у нужной Story — система назначит спринт задачам и посчитает прогноз дат.
5. **«Убрать»** — вернёт Story из спринта.

Вверху страницы — **Менеджер спринтов**:

- создать новый спринт;
- активировать другой;
- скопировать предыдущий;
- закрыть / отправить в архив;
- **перенести незавершённые** Story из старого спринта в текущий.

Активный спринт также можно сменить **в верхней панели** — это удобно, когда вы на другом экране.

### Движение работы по доске

1. Откройте **Поставка → Доска**.
2. Колонки — статусы Story (черновик, уточнение, готова, в работе, на ревью, готово…).
3. **Перетащите карточку** в нужную колонку **мышью** (вперёд или назад).
4. Можно также пользоваться кнопками переходов на карточке.

При переносе система автоматически:

- обновляет статус;
- пересчитывает прогноз дат задач;
- учитывает зависимости.

### Карточка User Story

Откройте Story **двойным кликом** или кнопкой **«Открыть»** (в бэклоге).

Справа откроется панель с:

- названием и статусом;
- форматом «Как / Я хочу / Чтобы»;
- приоритетом, типом, прогрессом;
- Acceptance Criteria (критерии приёмки);
- Definition of Done;
- списком задач (можно раскрыть описание, цель, ожидаемый результат);
- комментариями;
- быстрой сменой статуса.

### Контроль загрузки

1. **Сегодня** — краткая сводка и перегруженные люди.
2. **Аналитика → Загрузка** — подробнее по ролям.
3. **Система → Команда** — где задаются часы, отпуска и занятость (от этого считается Capacity).

## 6. Создание User Story (главный сценарий)

### Где создать

- форма на экране **Сегодня**;
- или из бэклога (если доступна форма создания).

### Что заполнить

1. **Название**
2. **Описание** (по желанию)
3. Карточка потребности:
   - **Как** — роль (например, «оператор ЦКИ»);
   - **Я хочу** — действие;
   - **Чтобы** — ценность для бизнеса.
4. **Тип** Story (функция/API, интеграция, документация и т.д.) — от типа зависит шаблон процесса по умолчанию.
5. **Приоритет**
6. **Шаблон процесса** — какие задачи создадутся автоматически.
7. **Шаблон оценки** — сколько часов подставить в каждую задачу.
8. **Спринт / Квартал / Релиз / Epic / Инициатива** — куда «привязать» Story (по возможности).

### Что произойдёт после подтверждения

Система сама:

1. создаст User Story с ключом вида `CKI-12`;
2. создаст все дочерние задачи по шаблону (BA, SA, Development, Testing…);
3. заполнит описания задач из шаблонов этапов;
4. проставит оценки часов;
5. построит зависимости между задачами;
6. при необходимости назначит исполнителей по правилам шаблона;
7. учтёт Story в Capacity.

Вам не нужно вручную «разбивать» Story на задачи с нуля — только уточнить оценки и детали в карточке.

## 7. Экраны подробно

### 7.1. Сегодня

Домашний экран. Отвечает на вопросы:

- какой сейчас квартал и спринт?
- не перегружена ли команда?
- как дела у релиза?
- что создавали недавно?

Отсюда же удобно создавать новые Story.

### 7.2. Квартал

**План → Квартал**

Показывает:

- цели квартала;
- дерево «Инициатива → Epic» и прогресс;
- давление по ролям (спрос часов / доступные часы).

**Менеджер кварталов** (на той же странице):

- создать квартал;
- активировать другой;
- архивировать;
- **скопировать структуру** (цели) из прошлого квартала;
- **перенести незавершённые** User Story в текущий квартал.

Активный квартал также переключается в **верхней панели**.

### 7.3. Спринт

См. раздел «Планирование спринта» выше.

Полезный приём в конце спринта:

1. Закройте или завершите старый спринт.
2. Активируйте новый.
3. Выберите «Перенести незавершённые из…» — незакрытые Story переедут вместе с пересчётом дат.

### 7.4. Бэклог

Список всех User Story продукта:

- ключ, название, статус;
- число задач и оставшиеся часы;
- открытие полной карточки.

Используйте бэклог, чтобы найти Story вне спринта или подготовить их к планированию.

### 7.5. Доска

Канбан по статусам Story.

- Перетаскивание **в любую допустимую** колонку (вперёд и назад).
- После переноса даты и прогресс пересчитываются.
- Подходит для ежедневного стендапа: «что сдвинулось».

### 7.6. Дорожная карта

Обзор сроков и связности работ во времени (прогнозные даты задач/Story).  
Удобно смотреть «не разъехался ли план» по календарю.

### 7.7. Релизы

Список релизов и готовность к выпуску:

- процент готовности;
- «ворота» (gates) — что ещё мешает релизу;
- состав Story в релизе.

На экране **Сегодня** и в верхней панели есть быстрый переход к активному релизу.

### 7.8. Загрузка / Риски / Пульс

| Экран | Смысл |
|-------|--------|
| **Загрузка** | Спрос vs предложение часов по ролям |
| **Риски** | Проблемные места плана (перегрузки, блокеры) |
| **Пульс** | Сводка «здоровья» продукта: прогресс, события, узкие места |

Состояние может быть: **В норме**, **Под риском**, **Срыв**.

### 7.9. Команда

**Система → Команда**

Управление сотрудниками:

- ФИО, роль, должность, команда;
- email (по желанию), цвет;
- часов в день, рабочих дней в неделю;
- максимальная загрузка (%);
- навыки;
- отпуска / больничные / праздники;
- комментарий;
- активен / неактивен.

Действия: создать, изменить, деактивировать, удалить.

**Важно:** Capacity команды считается из этих параметров. Изменили часы или добавили отпуск — загрузка на «Сегодня» и в аналитике обновится.

### 7.10. Шаблоны

**Система → Шаблоны**

Две большие части.

#### Шаблоны процессов (Workflow)

Список процессов (например, API, Интеграция, Документация).  
Нажмите на карточку шаблона — откроются **этапы**.

Для каждого этапа можно править:

- текст **описания** задачи;
- **цель**;
- **ожидаемый результат**;
- оценку часов по умолчанию.

Изменения применяются к **новым** User Story. Уже созданные Story не переписываются задним числом.

#### Шаблоны оценки

Готовые наборы часов, например:

- **API** — BA 4 / SA 6 / Dev 16 / Test 6;
- **Интеграция** — более тяжёлые оценки;
- **Документация** — свой набор этапов.

Можно:

- создать новый шаблон;
- изменить часы в строках;
- скопировать;
- удалить;
- назначить **по умолчанию**.

При создании Story вы выбираете, какой шаблон оценки подставить.

### 7.11. Миграция

**Система → Миграция**

Мастер переноса старой доски ЦКИ:

1. Загрузите файл **PDF** или **JSON**.
2. Просмотрите распознанные Story / спринты / релизы.
3. Выберите режим (полный перенос или частичный — по шагам мастера).
4. Подтвердите — данные появятся в CKI Flow.

Подходит, если раньше планы жили в PDF «Планы ЦКИ» или в экспортном JSON.

### 7.12. Настройки

- **Тема:** светлая / тёмная / как в системе.
- **Экспорт JSON** — скачать резервную копию всех данных.
- **Импорт JSON** — загрузить ранее сохранённый файл (заменяет текущие данные).
- **Сбросить демо-данные** — вернуть демо-набор (осторожно: текущие локальные правки пропадут).
- Ссылка на мастер миграции.

**Совет:** перед большим экспериментом сделайте **Экспорт JSON**.

## 9. Пошаговые сценарии

### Сценарий A. Новый функционал с нуля

1. **Команда** — убедитесь, что сотрудники и часы актуальны.
2. **Шаблоны** — при необходимости поправьте описания этапов или часы оценки.
3. **Сегодня** или форма создания — создайте User Story, выберите workflow + шаблон оценки + спринт.
4. Откройте карточку — дополните Acceptance Criteria и DoD.
5. **Спринт** — если Story ещё не в спринте, нажмите «В спринт».
6. **Доска** — двигайте Story по статусам по мере работы.
7. **Сегодня / Загрузка** — проверьте, не перегрузили ли кого-то.

### Сценарий B. Старт нового спринта

1. Создайте спринт в **Менеджере спринтов** (даты, название, цель).
2. Активируйте его (на странице или в верхней панели).
3. При необходимости перенесите незавершённое из прошлого спринта.
4. Наберите объём из готового бэклога кнопками «В спринт».
5. Смотрите бейджи нагрузки по ролям в шапке спринта.

### Сценарий C. Новый квартал

1. Создайте квартал (год, Q1–Q4, даты).
2. Активируйте его.
3. Скопируйте структуру целей из прошлого квартала.
4. Перенесите незавершённые Story.
5. На экране квартала проверьте давление по ролям — не слишком ли много demand.

### Сценарий D. Подготовка релиза

1. Откройте **Релизы** (или ссылку в шапке).
2. Посмотрите процент готовности и «ворота».
3. Вернитесь на **Доску** и доведите Story релиза до «Готово».
4. На **Сегодня** контролируйте статус релиза ежедневно.

### Сценарий E. Перенос старых планов

1. **Система → Миграция**.
2. Загрузите PDF или JSON доски.
3. Проверьте превью.
4. Примените миграцию.
5. Сверьте квартал/спринт в верхней панели и при необходимости активируйте нужные.

### Сценарий F. Отпуск сотрудника

1. **Команда** → выберите сотрудника.
2. Добавьте отсутствие (отпуск / больничный / праздник) с датами.
3. Откройте **Сегодня** или **Загрузку** — Capacity пересчитается, перегрузки станут видны раньше.

## 10. Статусы: шпаргалка

### User Story

Черновик → Уточнение → Готова → Запланирована → В работе → На ревью → Готово  
(также: Отменена, В архиве)

Перемещать можно **вперёд и назад**, если переход допустим правилами.

### Задача

Запланировано → Готово к работе → В работе → На ревью → Готово  
Отдельно: **Заблокировано**, Отменено.

### Здоровье плана

- **В норме** — всё стабильно;
- **Под риском** — есть перегрузки или блокеры;
- **Срыв** — сильная перегрузка / много блокировок.

## 11. Частые вопросы

**Где хранятся данные?**  
Локально на вашем Mac внутри приложения. Облака нет — для передачи коллеге используйте **Экспорт JSON**.

**Можно ли работать вдвоём в одной базе онлайн?**  
В текущей версии — нет. Это локальный инструмент PM. Синхронизацию через сервер планируют позже.

**Почему после правки шаблона старые Story не изменились?**  
Так и задумано: шаблоны влияют на **новые** Story. Старые карточки уже живут своей жизнью.

**Что делать, если случайно испортил данные?**  
Импортируйте ранее сохранённый JSON или нажмите «Сбросить демо-данные» (вернёт демо, не ваш бэкап).

**Приложение не открывается (Gatekeeper)?**  
ПКМ по приложению → «Открыть» → подтвердите. Либо разрешите в настройках безопасности macOS.

**Чем CKI Flow отличается от доски в PDF?**  
PDF — снимок. CKI Flow — рабочий инструмент: статусы, Capacity, зависимости, пересчёты, карточки и планирование без ручного редактирования структуры.

**Нужно ли вручную создавать задачи BA/Dev/Test?**  
Нет, если выбран правильный шаблон процесса. Задачи создаются сами; вы только уточняете.

## 12. Рекомендации по ежедневной работе

1. Начинайте день с **Сегодня**.
2. Держите актуальными **команду и отпуска** — иначе Capacity врёт.
3. Создавайте Story через форму с выбором **workflow + оценки** — не копируйте задачи руками.
4. Планируйте спринт кнопками «В спринт», а не правкой «внутренностей».
5. Перед крупными изменениями делайте **Экспорт JSON**.
6. В конце спринта используйте **перенос незавершённых**, а не ручное пересоздание.
7. Смотрите **перегруженных сотрудников**, а не только суммы по ролям.
